# Digital Teaching Materials

The signed-in home uses the university's three-column layout, notice icons, course-category tree and Open Sans. Course pages use the observed two-column Moodle layout: course title and breadcrumb, important information, selected-course navigation and contacts, plus assignment, quiz and material sections. The course grade report uses the source's eight columns, report tabs, course grouping and sidebar administration block. Missing weights, ranks, contributions and calculated course totals remain dashes; the records model does not provide quiz types or official grade calculations.

`/dtm/login` uses Google sign-in. `/dtm` follows the official three-column layout with navigation, announcements, course categories and contact details checked on 2026-11-12. `/dtm/dashboard` and `/dtm/my` use the observed profile header, important-information/navigation/contact sidebar and empty center block region. All saved courses remain grouped by term in the navigation. The empty block region is a presentation choice based on the captured account layout, not a claim that a user has no courses or that all university dashboards are empty. The English and Traditional Chinese choices update the interface and the page language metadata used by browsers.

DTM and School Affairs use the same Google session. Sign-in returns to the requested DTM page. The homepage account indicator and assistant use the same verified identity. Old `/school-sites/dtm.stu.edu.tw/` links open the local DTM.

Add a personal course from the existing account menu. Its dialog reuses the personal record editor and opens the saved course after creation. Cancel does not write; a failed save retains the entered fields. The gear menu on a course opens materials, class meetings, assignments and grades, creates records, imports deadlines, or edits/deletes the course. Select an assignment, material or grade to read its details and edit/delete your record. Class-meeting rows retain their attendance and editing actions. Link an assignment to the meeting where it was given. `/dtm/assignments` and `/dtm/grades` aggregate the saved records. The seed course stays labeled as a sample. The site administrator's existing manager covers sample records, and RLS restricts personal DTM records to their owner. The participants dialog shows only the current account; it does not imply access to a university roster. The account menu retains the campus assistant.

The source's Customize this page control edits persisted block layout/content; it is separate from course creation and is not implemented here. No inactive imitation control is rendered. See [dashboard QA](../../../../docs/qa/DTM_DASHBOARD.md) for the measured layout, offline checks and remaining visual/customization limits.

The dashboard footer follows the observed three-column structure: local caller identity and working logout, an empty middle column, source social links on the right, and theme attribution below. The identity link opens this account's local records; the school-home icon opens the copied local homepage. Privacy remains in the account menu. External social destinations, including the source's retired Google+ link, are preserved as observed references and are not claimed to be functional. Course creation captures the expected caller and aborts on editor unmount; a changed session is rejected before the POST even when session lookup was still pending.

To import deadlines, download a Moodle Calendar `.ics` file, choose the matching saved course, and select the deadlines to import. The import stores titles, Taipei-normalized dates and a deduplication hash. Calendar feed URLs, descriptions and credentials stay out of storage. The assistant can link to the selected meeting's assignments, unfinished work, attendance and grades from this account.

Official enrollment, university submissions, notifications and grade synchronization require a university-approved Moodle integration. Local file submissions are independent stu.best records. [Moodle calendar export](https://docs.moodle.org/502/en/Using_Calendar), [Moodle external services](https://moodledev.io/docs/4.5/apis/subsystems/external).

`tests/integration/dtm-course-ui.mjs` verifies the observed 1533px desktop geometry, course and grade navigation, record details, assignment create/edit/delete requests, phone widths and accessibility against synthetic account-scoped responses. Screenshots are ignored under `artifacts/dtm/`. It does not prove live database persistence; the deployed student workspace and RLS suites cover that boundary.

`DtmSubmissionWorkspace` mounts `DtmAssignmentDetail` and `DtmSubmissionEditor` at `/dtm/course/:course/assignment/:assignment[/edit]`. The page separates submission state, review state, due date, timing and submitted files. Saved and pending revisions remain independent; uncertain retries retain the operation ID, and account changes abort and hide the previous account's work.

Migration `20261112150000_dtm_submissions.sql` is applied. Each account-owned assignment has at most one current file and one pending reservation, with a **10 MiB** local limit. Upload/replace/cancel use optimistic versions and durable receipts. A verified School Affairs administrator can review a specific saved revision in the existing record manager; replacing a file does not inherit its former grade. Personal tracker statuses remain distinct from actual submissions.

The helper budgets each operation to 12 seconds or the caller's earlier deadline. Cleanup deletes at most five server-selected queued paths within eight seconds; failures preserve the durable receipt and queue. Managers have an explicit bounded cleanup control for discarded files, including deleted-account leftovers. Download capabilities expire after 60 seconds; file bytes, names, paths and signed URLs stay out of general assistant snapshots.
