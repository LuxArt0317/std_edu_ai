# School Affairs assistant — Issue #87

The public and Google-signed-in School Affairs chat now has a separate answer path from the Nexus operating assistant. `api/affairs-assistant.ts` verifies the School Affairs bearer session through Supabase Auth, but does not query Nexus courses, students, terms, schedules or knowledge that is limited to staff. Public questions are handed to `api/research-assistant.ts` without account identity, authorization or prior private conversation history. Account questions use only the verified stu.best identity. Official school enrollment, grades, timetable, fees and individual notices remain unavailable until an authorized school integration exists; the answer links the relevant captured service instead of presenting demo data as enrollment.

The 94 captured service links in `src/features/public/affairs/catalog.json` are available through `server/schoolAffairsDirectory.js`. Exact service, group and current-menu questions return local navigation plus the official service URL. The directory is a November 2026 snapshot, not proof that the destination remains open or that its contents are authorized for the visitor. Other public school questions continue through managed public knowledge and official/broader STU web search with validated citations. Nexus titles and demo course/term markers are excluded from that retrieval and live web answers.

The drawer accepts up to two PNG, JPEG or WebP images under 1.5 MB each. The API checks the data URL, byte count and file signature. Submitted images go to the configured OpenAI model with `store:false`; image contents are not sent to public web search, written to the knowledge base or saved in chat history beyond page memory. The response is grounded in visible image content and matching captured service entries, not assumed private university records. The “How I checked” panel reports completed retrieval, search and image actions; it does not expose private model reasoning.
